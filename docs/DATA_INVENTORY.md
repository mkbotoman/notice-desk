# Data inventory

Every kind of data the app stores or handles: where it comes from, how sensitive it is, who can
see it, and what happens to it. All people and companies in the sample data are made up, but it is
handled as production data would be.

Classification: **public**, **internal**, **confidential**, **sensitive PI** (personal information
the law singles out, such as an SSN).

## Removing one person's data

Guarantor names live in their own file, `data/seed/guarantors.json`, keyed by case id; the cases
themselves hold only `hasGuarantor`. To honour a deletion request, delete that person's entries
from the file and re-deploy. Every case, event and report entry stays intact. Notes typed in the app
are in browsers only; they never reach a server.

## Known limitation: guarantor names reach every viewer's browser

The prototype has no server-side data layer. The seed is loaded on the server and passed to the
page, so guarantor names are present in the page HTML and the browser's memory for **every**
persona, including those without `view_guarantor`. The permission check hides them in the
interface; it does not stop someone reading the page source. Personas are also selectable by anyone
past the password gate. This is accepted for sample data. A real build would keep guarantor data
behind an authenticated API that checks the caller's role on the server.

## Not collected

No analytics scripts, no third-party trackers, no logging of case contents, no personal data in
URLs (URLs carry ids and filters only).
